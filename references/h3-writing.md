# H3 编写规则与来源

核对日期：2026-10-26。以下来源是写作依据，不构成对所有生成端的格式兼容保证。

## 来源与使用边界

- MiniMax 官方概述：https://www.minimax.io/blog/minimax-h3
  已核验的核心方法：用自然语言说明不同素材如何贡献外观、运动、运镜、声音等。官方概述没有证明下列所有字段和标签都是强制接口语法。
- 用户指定结构参考：https://minimaxh3.co/prompt-guide
  提供 Base 和 Full-Reference 两种组织方法，自称基于官方指南；本次未核验其原始指南。其字段、保留标记和时间标注作为第三方模板约定使用。
- 用户指定实用参考：https://minimax-h3.app/prompt-guide
  明示独立服务、非 MiniMax 官方；强调具体动作、清晰运镜、参考分工及结束状态。

不要使用“Codex 2.5 视频语法”“Codex 四步标准”或未经核实的 Camera Sequence 命令。Codex 是执行此技能的助手，不是这里的视频模型格式名称。

若用户使用的入口有明确格式要求，优先核验其当前官方文档，再适配；否则使用清晰自然语言。不要将第三方页面声称的分辨率、时长、价格、英文限定或语法当成官方硬性要求。网页变化时重新核验，记录来源差异，不机械覆写用户已确认偏好。

## 本技能采用的组织方法

下面是为本技能整理的写作约定，而非官方必填 API 参数。根据任务选一种，不同时堆叠多个格式。

### 基础模式

适用于纯文字复现或以真实图像为首尾锚点的生成：

- `integrated_multimodal_description`：按时间展开画面、动作、运镜及确知的同步声音。
- `overall_soundscape`：已知的整体环境声和物理声；与正文分工，不重复台词。
- `non_diegetic_music`：确知或用户要求的画外配乐。

字段名可保持英文，字段内容分别给中文和英文。未知音轨在块外声明“音频未分析”，不将未知写成 `N/A` 或“静音”；可省略未确定音频字段，明确这是视觉反推版本。用户要求无配乐时才写相应无配乐指令。

首尾帧仅在真实提供时添加对齐说明。叙述锚点之间的连续变化，不只重复两张静态图。

### 多素材参考模式

采用六部分组织内容：

1. `subject_definitions`：角色和其他被引用内容，逐一绑定真实素材及用途。
2. `summary`：目标及参考关系。
3. `retention_analysis`：具体保留、改变和迁移哪些特征。
4. `detailed_description`：按播放顺序描写镜头与动作。
5. `overall_soundscape`：已知环境声音及音频参考作用。
6. `non_diegetic_music`：已知或指定的画外配乐。

若声音无法取得，块外说明未分析，并省略对应未知字段，不能为凑齐模板发明声音。此时标为本技能的视觉适配版。

优先使用生成端实际预览标签。尚未上传时提供“待上传素材对应表”，不声称已绑定。区分角色内容、帧锚点、整个视频的节奏/运镜作用与音频作用。同一视频可提供多种信息，但每种作用要明确。

角色替换示例：角色图控制新主角外观；视频控制被替换角色的动作时序与运镜；保留哪些环境、配角和道具另行说明。不要写“完全保留原主角”又要求替换其外观。只有动作迁移不等于直接编辑原视频。

### 时间、镜头与声音

可用 `[Shot 1]` 等镜头标识。采用指定结构参考的约定时，第一镜头不加切镜时间，后续切镜使用递增的片内时间；分析表仍记录原片起止时间。不要给不确定切点写虚假的精确小数。

动作与运镜使用有方向、有起止的自然语言。多阶段运镜可以存在，但须按顺序描述，不能同时给相互矛盾的运动指令。

对白绑定稳定说话者；格式标签仅在入口已核验支持时使用，普通自然语言也是默认可用组织方式。环境声、同步事件声和画外音乐分工描述。实际声音与建议新增声音必须区分；没有听音证据时不推断歌曲名、BPM 或原声内容。

## 双语规则

本技能按用户要求提供分开的完整中文及英文版本。网站的英文优先约定不覆盖此偏好。两版保留相同素材标识及镜头编号；原声语言和可见文字不因正文翻译而改变。如果某个入口经核验仅支持特定语言，明确哪一版适合提交，另一版用于阅读核对。

## 最终附件绑定

最终输出须执行 [附件绑定与上传顺序](attachment-binding.md)：将真实首帧和已采用的角色、环境、道具参考的编号与用途写入提示词，另附逐段上传清单及顺序提醒。编号是本 Skill 的素材对应约定，使用时与生成端实际标签核对。
